# malm-format-component-host

`malm-format-component-host` admits and runs an untrusted WebAssembly component
implementing `format-component/v1`. It is for runtime maintainers and embedders;
most applications connect it to Engine through `malm-format-component-adapter`.

The trusted host receives authorization, an expected digest, and exact component
bytes. It admits those bytes, then invokes `transform` with a validated
typed document, explicit options, and declared resource bytes. Every invocation
uses fresh bounded runtime state.

## Admission

`FormatComponentHost::admit_component` groups its checks around:

1. Policy and identity: authorization, the 16 MiB input limit, and the SHA-256
   digest of the exact bytes.
2. WebAssembly shape: component encoding rather than a core module, the fixed
   feature set, successful compilation, and no root imports.
3. Contract: successful pre-instantiation against the one required WIT world.

The resulting `AdmittedFormatComponent` remains bound to its verified digest and
the host's fixed execution-profile digest.

## Sandbox

The WIT world has no imports, and the host supplies none. Components receive only
their request: no WASI, filesystem, network, environment, process, clock,
randomness, Malm state, or target access. Fixed limits cover fuel, aggregate
memory, tables, instance resources, stack, and guest-to-host transfer.

## Results

`AdmittedFormatComponent::transform` returns a nested result. The inner result is
a valid semantic success or failure: failures may be returned by the component,
or generated by the host when fuel, memory, table, instance, or transfer limits
are exhausted. The outer error covers invalid requests, malformed component
output, guest traps, runtime failures, and infrastructure cancellation. Callers
must handle both levels.

The host does not select or fetch components, parse configuration, or persist
state. Its public API does not expose runtime internals.
